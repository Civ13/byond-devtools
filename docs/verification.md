# Initial verification

Executed in a Linux cloud workspace, Node.js v24.22.1, on 2026-11-07.

- `npm test`: 34/34 tests passed, no skips.
- `npm run check`: all four source files passed Node syntax checks.
- Actual Gaia source inspected from Civ13/Civ13 commit
  `21f0473a047c3cbd9831b107a276049a4f708dc3`, path
  `maps/nomads/nomads_gaia.dmm`, source Git blob
  `52ea621a3d10855a3ef3447d2028e17e2af34803`.
- Parsed 350,000 cells, bounds (1,1,1) through (500,350,2), 255 dictionary
  definitions, 99 distinct placed type paths.
- The downloaded test copy had one added trailing newline from transfer; semantics
  match the source. The map is not included in this repository. Do not interpret
  its local SHA-256 as the upstream byte identity.
- Synthetic tests cover equivalent full-plane and TGM column orientation, offset
  blocks, duplicate objects and aliases, frozen snapshots, search pagination,
  escaped values, comments, invalid/overlapping/undefined data, safe-integer
  overflow, resource limits, root containment, symlink escape, UTF-8 validation,
  CLI errors/provenance and a generated 350,000-cell workload.

Not run: native BYOND compilation/round-trip, DMI rendering, GUI tests, Windows or
VS Code Stable/Insiders tests, runtime/gameplay/persistence acceptance. There is
no serializer or edit operation, so this proves no-op observation only, not an
edit-save round trip. CI was added afterwards; see the CI section below.

Single local Gaia timing sample (not an editor benchmark): parser 28.7 ms, summary
110.1 ms, process RSS 57.3 MiB. Hardware/runtime/cache state was not controlled;
do not interpret this as a performance guarantee. Input source remained identical.

Pinned Civ13 DME lexical inventory returned 1,462 includes; conditional activation
remains unknown. Gaia subtype query found 141 mob-spawner cells and correctly
returned one bounded result with a truncation flag.

Focused review found and fixed output amplification by shared overrides and a
multiline-string include false positive. Added regression tests; search now
returns compact coordinate/key references, and CLI JSON has a conservative 16 MiB
preflight budget. Summary counts are aggregated by dictionary-key occupancy.

## Continuous integration (phase 1, 2026-11-07)

`.github/workflows/ci.yml` runs `npm run check` and `npm test` on ubuntu-latest and
windows-latest with Node 22 and 24. A second job sparse-checks-out Civ13/Civ13
`maps/` at its default branch head and runs `scripts/corpus.js`, which fails on any
parse error or on fewer than 250 maps. Locally on Civ13 master e3a34ff: 279/279
maps parsed (15 TGM style, 0 CRLF), 15,956,920 cells, about 2.6 s.

Windows-specific tests use a junction for the escape test (directory symlinks need
admin rights there), and check drive-letter, UNC, drive-relative and
case-insensitive project paths. Those branches run only on the Windows jobs.
The corpus job checks Civ13's own line endings (`*.dmm eol=lf`); whole-file CRLF
input is covered by a unit test instead.

## Static rendering (phase 5, 2026-11-07)

`fixtures/render/project` is an original fixture project (icons generated by
`scripts/make-render-fixtures.js`, 8 px world). Its type tree and the instance values of
nine types were recorded with DreamMaker/DreamDaemon 516.1688; every resolved render var
(icon, icon_state, dir, layer, plane, pixel offsets, color, alpha, invisibility) matches.
`test/render.test.js` compares a golden render pixel for pixel and checks layer order over
stack order, dir frames, pixel offsets, tint and alpha blending, bottom-left anchoring of a
16x16 icon, placeholders and diagnostics by hand-computed values. The native CI job
re-records the fixtures and fails on any difference.

On Civ13 master locally, a 64x64 crop of Gaia z2 and of 1943 Berlin rendered in about
2.5 s each with no missing icons or states. Berlin reported 6 `unknown-type` placements
(`su100` track parts that `lint` also flags) and skipped invisible landmarks. Not done:
comparison with a Dream Seeker screenshot, and the cross-tile order of equal-layer
sprites, which is assumed to be south over north.

## Safe map edits (phase 6, 2026-11-07)

`scripts/edit-corpus.js` makes three sample edits on every Civ13 map, in memory and in a
temp folder only: one cell takes another cell's stack, one gets a new var-edited obj, and
one gets a replaced obj. On Civ13 master all 279 maps (718 edits, 558 new keys) pass:

- Civ13's mapmerge2 loads each edited map and writes it back byte for byte. 91 maps
  are rewritten by mapmerge2 even unedited; for those the check runs on mapmerge2's own
  output, edited, and all 91 are stable.
- `scripts/maplint.py` reports no errors that the original map did not already have.
- The inverse patch restores every cell.

`test/edit.test.js` covers exact DMM, TGM and CRLF output, key reuse and ordering, stale and
unsafe patches, a full key space, the atomic file apply (BOM, no temp file left, stale base)
and the CLI. With `BYOND_BIN` set, an edited fixture map is loaded in DreamDaemon 516.1688
and agrees cell by cell with the parser, including the new overrides. The corpus check runs
in CI on Linux and Windows. Not run: an edit to a map followed by a full-game compile.

## In-game render (phase 5b, 2026-11-07)

`fixtures/render/project/ingame.dme` is a fixture world whose `New()` procs change an icon
state, add an overlay, set a colour matrix and turn an object, plus a lighting-style plane
master (multiply, constant alpha). `fixtures/render/ingame.dump.json` is its recorded dump
from DreamDaemon 516.1688. `test/ingame.test.js` checks the dump holds those runtime changes
and checks rendered pixels by hand-computed values: the master's half light, a lamp on the
master's plane restoring full light, the 90 degree clockwise turn with its overlay, the
colour matrix and invisibility. With `BYOND_BIN` set it re-records the dump and requires an
exact match (CI native job). The Civ13 probe (`civ13` profile) compiles with 0 errors
against Civ13 master in CI; it is not booted there.

Not verified: a Civ13 boot and render (needs a separate go-ahead to run game code), and any
comparison with Dream Seeker. The compositor's blend and plane-master semantics follow
BYOND's documented behaviour and have not been checked against a client screenshot.

## VS Code preview (phase 7, 2026-11-07)

`test/vscode-session.test.js` checks the viewer's session logic with node:test: summary,
inspection, the golden render pixel for pixel, clipping, and the messages shown when no
type tree is configured. `vscode/integration` runs inside a downloaded VS Code: it opens the
fixture map with the custom editor, checks the missing-settings message, renders the
golden image through the extension, inspects a cell, and checks the map is unchanged and
no document is dirty. CI runs it on Stable and Insiders, Linux and Windows. VS Code
downloads are blocked in the cloud session, so that suite ran only in CI. The webview's
look was not checked by a person.
